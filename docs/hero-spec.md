# Hero Keyword Interaction — Spec

> 상태: 최종본 v1.1 (칩 자유 배치 추가) · 작성자: 이세비
> 기준 디자인: Figma `v2 — Pages`, `v2 — Design System`
> 스택: Next.js (App Router) · TypeScript · Tailwind CSS v4 · Motion · next-themes · Vercel

---

## 0. 목적과 성공 기준

이 인터랙션은 "직접 써보고, 흐름이 끊기는 곳을 다듬는 개발자"라는 주장을 **키워드 = 실제 성과**로 연결해 보여준다.

- [ ] 처음 방문한 사람이 설명 없이도 키워드를 넣어볼 수 있다
- [ ] 키워드를 넣지 않는 사람도 첫 화면에서 이름·핵심 문구·이동 경로를 읽을 수 있다
- [ ] 키보드만으로, 애니메이션 줄이기 설정에서도 같은 정보를 얻을 수 있다

**확인 방법**: 개발하지 않는 지인 2~3명에게 설명 없이 써보게 하고 관찰한다. (기록: 어디서 멈췄는지, 무엇을 눌렀는지)

## 1. 용어

| 용어 | 의미 |
|---|---|
| Slot | `I'm 세비 [ ___ ] Developer.` 안의 빈칸 |
| Keyword Pill | 성과 키워드 9개. 넣으면 문장과 서브 문구가 바뀜 |
| Nav Pill | `프로젝트 →`, `아티클 →`. 넣으면 "○○를 구경해봐요" 후 페이지 이동 |
| Hero Copy | Eyebrow + Headline(이름·슬롯·꼬리말) + Subcopy + Hint |
| Ring (고리) | 데스크톱에서 Hero Copy를 타원형으로 둘러싼 칩 배치 |
| Home 위치 | 각 칩의 Ring 위 원래 자리 (7장 계산값) |
| 자유 배치 | 칩을 슬롯이 아닌 곳에 놓으면 그 자리에 머무는 것 (데스크톱만) |
| 정리 버튼 | 흩어진 칩을 모두 Home 위치로 되돌리는 버튼 |

## 2. 데이터

위치: `content/keywords.ts`

```ts
type HeroKeyword = {
  id: string;            // kebab-case 영문 (예: 'rewrite', 'bundle-47')
  label: string;         // 칩·슬롯에 보이는 글자
  type: 'keyword' | 'nav';
  subcopy?: string;      // keyword일 때. 줄바꿈은 '\n'으로 직접 지정 (Figma와 동일)
  href?: string;         // nav일 때 ('/projects' | '/articles')
  trailing?: string;     // nav일 때 꼬리말. 조사는 직접 지정 ('를 구경해봐요.' / '을 구경해봐요.')
  projectSlug?: string;  // 관련 프로젝트. 데이터만 넣어두고 UI 연결은 나중에
  ring?: { rotate: number }; // 기울기(°)만 지정. 위치는 순서로 자동 계산 (7장)
};
```

|---|---|---|---|---|

| e2e | E2E로 검증하는 | keyword | 실제 사용자처럼 화면을 조작하는 테스트(E2E)를 쓰다, 작성 중 페이지를 나가도 경고가 뜨지 않던 버그를 찾았습니다.\n고친 뒤 뒤로가기·새로고침·탭 닫기 세 경우 모두 테스트로 확인했습니다. | jikyeojwo-homes |

### 순서
- **데스크톱 Ring**: 위쪽 가운데부터 시계 방향, Figma v2 순서 그대로
  `rewrite → e2e → go-projects → bundle-47 → coverage-72 → seo → volunteer → go-articles → ai-criteria → new-domain → feedback`
- **모바일 칩 목록**: `go-projects → go-articles → bundle-47 → coverage-72 → 나머지(Ring 순서)`

## 3. 상태

```
 [Empty] ──keyword 넣기──▶ [Filled(k)] ──다른 keyword 넣기──▶ [Filled(k2)]
    ▲                          │
    └──── 슬롯 안 칩 탭 ────────┘

 [Empty | Filled] ──nav 넣기──▶ [Navigating(target)] ──1.2s──▶ 페이지 이동
                                        └──클릭──▶ 즉시 이동

 드래그 중 슬롯 밖에 놓음 ──▶ 상태 그대로, 칩은 놓은 자리에 머묾 (자유 배치)
 드래그 중 Esc            ──▶ 상태 그대로, 칩은 드래그 시작 전 자리로 복귀
 정리 버튼                ──▶ 상태 그대로, 모든 칩 Home 위치로 복귀
```

| 현재 | 이벤트 | 다음 | 비고 |
|---|---|---|---|
| Empty | keyword 넣기 (드래그 / 클릭 / Enter / 탭) | Filled(k) | k는 Ring에서 빠짐 |
| Filled(k) | 다른 keyword 넣기 | Filled(k2) | k는 **Home 위치**로 복귀(자유 배치됐던 자리 아님), k2는 Ring에서 빠짐 |
| Filled(k) | 슬롯 안의 칩 탭 / 클릭 / Enter | Empty | k는 **Home 위치**로 복귀 |
| Empty·Filled | nav 넣기 | Navigating | Ring 숨김 |
| Navigating | 1.2s 경과 | 페이지 이동 | |
| Navigating | Hero Copy 클릭 | 즉시 이동 | |
| Navigating | 칩 드래그 시도 | 무시 | |
| 드래그 중 | 슬롯 밖에 놓음 | 이전 상태 | 칩은 **놓은 자리에 머묾** (화면 가장자리 안쪽으로 보정, 4장) |
| 드래그 중 | Esc | 이전 상태 | 칩은 드래그 시작 전 자리로 복귀 |
| 아무 상태 | 정리 버튼 | 이전 상태 | 자유 배치된 칩 모두 Home 위치로 복귀. 슬롯에 들어간 칩은 그대로 |

- 같은 keyword를 다시 넣는 경우는 없음 (넣은 keyword는 Ring에서 사라지므로)
- 상태 저장: 히어로 컴포넌트 안 `useReducer` (전역 상태 라이브러리 없음)
  - `slot: id | null`, `navigating: id | null`, `placed: Record<id, { x: number; y: number }>` (자유 배치 위치, Hero 영역 기준 **비율 0~1**), `stack: id[]` (겹침 순서)
- URL 반영: 하지 않음 (추후 `?k=` 추가 가능하도록 reducer는 id 기반으로 작성)
- 새로고침: Empty, 모든 칩 Home 위치 (자유 배치는 저장하지 않음)
- 이동 후 뒤로가기로 돌아옴: Empty, 모든 칩 Home 위치

## 4. 입력

| 입력 | 데스크톱 | 모바일 (< 브레이크포인트) |
|---|---|---|
| 포인터 드래그 | 지원 | 미지원 (스크롤과 충돌) |
| 클릭 / 탭 | 지원 (= 슬롯에 넣기) | 지원 (주 입력) |
| 키보드 | Tab으로 칩 이동, Enter·Space로 넣기, 드래그 중 Esc로 취소 | — |

### 드롭 판정
- 구현: **Motion `drag` + 직접 판정**
- 판정 기준: 놓는 순간 **포인터 좌표**가 슬롯 영역 안
- 슬롯 영역: `getBoundingClientRect()` + 사방 **16px** 여유
- 클릭/드래그 구분: **5px** 이상 움직이면 드래그, 미만이면 클릭
- 드래그 중 칩이 슬롯 위에 있을 때: 슬롯 테두리 점선 → **실선 `brand/orange`**, 슬롯 `scale(1.03)`
- 놓은 위치가 슬롯 밖: 칩은 **그 자리에 머묾** (자유 배치)

### 자유 배치 (데스크톱만)
- 위치 저장: Hero 영역 기준 비율(0~1) → 창 크기가 바뀌어도 같은 비율 위치 유지
- 화면 밖 보정: 칩이 Hero 영역 밖으로 나가면 가장자리 안쪽(여백 **16px**)으로 붙임. Nav 영역 위에는 놓이지 않음
- 가림 허용: 칩이 Hero Copy(이름·서브 문구)나 **다른 칩 위에 겹쳐도 됨**. 밀어내지 않음
- 겹침 순서: **마지막으로 잡은 칩이 맨 위**. 드래그 중인 칩은 항상 최상단
- 기울기: 자유 배치해도 원래 `ring.rotate` 유지
- 슬롯 판정 우선: 놓은 순간 포인터가 슬롯 영역 안이면 자유 배치가 아니라 슬롯에 넣기
- 모바일(768px 미만): 자유 배치 없음 (드래그 자체 미지원)

### 정리 버튼
- 표시 조건: 자유 배치된 칩이 **하나 이상**일 때만 보임
- 위치: Hint 줄 오른쪽, 같은 글자 스타일(`mono/xs`)의 텍스트 버튼 — 라벨 `칩 정리하기` (Figma에 아직 없음, 디자인 추가 필요)
- 동작: 모든 자유 배치 칩이 Home 위치로 spring 복귀, `placed` 비움
- 키보드: Tab으로 도달, Enter·Space로 실행

## 5. 화면 반응

### Filled
- 슬롯: `accent/selected` 배경, 글자 `text/on-selected`, 모서리 핸들 4개 (`accent/handle`, 슬롯 크기에 맞춰 꼭짓점 고정)
- Headline 꼬리말: `Developer.`
- Subcopy: 해당 keyword의 subcopy로 교체 (6장 애니메이션)
- Hint: **계속 표시**

### Navigating
- Headline: `I'm 세비 [프로젝트 →] 를 구경해봐요.` / `I'm 세비 [아티클 →] 을 구경해봐요.`
- Subcopy: `잠시 후 프로젝트 목록으로 이동합니다.` / `잠시 후 아티클 목록으로 이동합니다.`
- Ring: 페이드 아웃
- Hint: 계속 표시
- 대기: **1.2s**, Hero Copy 클릭 시 즉시 이동

## 6. 애니메이션

라이브러리: **Motion**

| 대상 | Figma 값 | 코드 값 |
|---|---|---|
| 칩 호버 | 0.18s ease-out | `duration: 0.18, ease: 'easeOut'` |
| 칩 → 슬롯 이동 | Smart Animate Gentle 0.6s | shared layout (`layoutId`) + spring (`stiffness`, `damping`은 구현 후 직접 써보며 조정) |
| Subcopy 교체 | — | 이전 문구 페이드 아웃 → 새 문구 **페이드 + 위로 8px 등장**, 각 0.25s |
| Ring 숨김 (Navigating) | 페이드 | opacity 0, 0.3s |
| 자유 배치 놓기 | — | 놓은 자리에서 살짝 안착(spring, 이동 없음) |
| Esc 복귀 · 정리 버튼 · 슬롯에서 빠진 칩의 Home 복귀 | — | spring |
| 페이지 전환 | Dissolve 0.3s | **없음** (기본 이동) |
| 프로젝트 카드 호버 | 0.2s | `duration: 0.2` |

- `prefers-reduced-motion: reduce` → 모든 이동·등장 생략, 상태는 즉시 바뀜 (드래그 자체는 허용)

## 7. 레이아웃

### 데스크톱
- 기준 화면: 1512 × 982 (Figma)
- Hero Copy 블록: 화면 가운데 배치, 블록 안은 **좌측 정렬**, 폭 846px 고정 (가장 긴 키워드 기준 → 키워드가 바뀌어도 이름 위치가 흔들리지 않음)
- Ring: 칩 위치는 **각도로 자동 계산**
  - 칩 i의 각도 = `-90° + i × 360° / 칩 개수` (위쪽 가운데에서 시계 방향, 2장 순서 기준)
  - 좌표 = 타원 중심 + (rx·cos, ry·sin), 칩의 **중심**을 그 좌표에 둠
  - 기준값(1512px 폭): 중심 (756, 528), rx 610, ry 330 / 기울기는 데이터의 `ring.rotate` (−6°~5°)
  - Filled 상태에서 슬롯에 들어간 칩의 자리는 **비워둠** (다른 칩이 재배치되지 않음 → 이전 칩 복귀 위치가 항상 같음)
- Ring 크기: **화면 폭에 비례** — rx, ry, 중심을 `화면 폭 / 1512` 비율로 계산 (칩 자체 크기는 고정)
- 충돌 규칙: **Home 위치**의 칩은 Hero Copy 블록(Headline·Subcopy 영역)과 겹치면 안 됨. 겹치면 rx·ry를 블록 바깥까지 키움 (최소 반지름 = 블록 절반 크기 + 칩 높이). 사용자가 자유 배치한 칩은 이 규칙에서 제외
- Hero Copy 블록 폭: `min(846px, 화면 폭 − 좌우 여백)`

### 768px ~ 1023px 구간 (주의)
- 이 구간은 Ring을 유지하지만, 블록과 칩 사이 공간이 가장 좁음
- 확인 폭: **768 / 900 / 1023px**에서 가장 긴 키워드(`Feedback으로 다듬는`)를 넣은 상태로 겹침이 없는지 테스트 (12장 #14)
- 겹침을 피할 수 없으면: 이 구간만 칩 기울기 0°, 칩 글자 크기 한 단계 축소 → 그래도 겹치면 브레이크포인트 재검토

### 모바일
- **전환 폭: 768px 미만**
- 구조: Nav → Hero Copy → 칩 목록 (줄바꿈, 회전 없음)
- 슬롯 안내 문구: `키워드를 탭해보세요` / Hint: `키워드를 탭하면 문장이 바뀌어요`
- 텍스트 줄바꿈: `word-break: keep-all`

## 8. 테마

- 구현: `next-themes`, `attribute="data-theme"`, `defaultTheme="system"`, `enableSystem`, storageKey `sebi-theme`
- 동작
  - 저장된 값이 없으면 OS 설정을 따름 (OS 다크 → 첫 화면 다크, 토글도 달)
  - 토글을 누르면 그 값이 localStorage `sebi-theme`에 저장되고, 이후 방문은 OS와 무관하게 저장된 값
  - 한 번 고른 뒤 OS 설정이 바뀌어도 따라가지 않음 (의도된 동작)
- 토글: 해/달 2단 (Figma `Theme Toggle`)
- 색: CSS 변수만 바뀜 → 테마 전환 시 컴포넌트 리렌더 없음
- 첫 화면 깜빡임: `next-themes`의 페인트 전 스크립트로 방지, `<html suppressHydrationWarning>`

### 사용 토큰 (Sebi Light / Sebi Dark, 같은 이름·다른 값)
`brand/orange`, `brand/orange-text`, `accent/selected`, `text/on-selected`, `accent/handle`, `bg/inverse`, `text/inverse`, `bg/page`, `bg/surface`, `border/default`, `text/primary`, `text/secondary`, `text/muted`, `text/placeholder`

## 9. 서버 렌더링 / SEO

- 첫 HTML에 포함: Eyebrow, Headline(Empty), 기본 Subcopy, Hint, 모든 칩 라벨
- 키워드별 subcopy는 첫 HTML에 넣지 않음 (같은 내용은 프로젝트 상세 페이지가 담당)
- Nav Pill은 실제 링크 `<a href>`로 렌더링 → 검색엔진이 `/projects`, `/articles`를 따라감. JS가 동작하면 클릭을 가로채 Navigating 연출 후 이동
- 하이드레이션 전후 레이아웃 변화 없음 (CLS 0 목표)

## 10. 접근성

- Keyword Pill: `<button aria-pressed>` (슬롯에 들어간 상태면 true)
- Nav Pill: `<a>` (9장)
- 슬롯: `aria-label="키워드를 넣는 칸"` (Empty) / `"○○ 선택됨, 누르면 비우기"` (Filled)
- 상태 안내: Subcopy 영역 `aria-live="polite"`
  - Filled: `"○○ 키워드를 넣었습니다. " + subcopy`
  - Empty로 리셋: `"키워드를 비웠습니다."`
  - Navigating: `"잠시 후 ○○ 목록으로 이동합니다."`
- 포커스: 키워드를 넣은 뒤에도 **그대로** (누른 칩 자리. 칩이 Ring에서 빠지면 다음 칩으로)
- Tab 순서: 화면 위치나 겹침 순서와 무관하게 **항상 2장 Ring 순서** (자유 배치로 위치가 바뀌어도 키보드 순서는 고정)
- 자유 배치는 포인터 전용 장식 기능. 키보드·스크린리더 사용자는 기능상 잃는 것이 없음
- 칩이 Hero Copy를 가려도 텍스트는 DOM에 그대로 있어 스크린리더는 읽음
- 정리 버튼 실행 시 안내: `"키워드를 원래 자리로 정리했습니다."`
- 색 대비: 라이트 `brand/orange-text` 4.5:1 이상, 다크 `text/on-selected` 8.5:1

## 11. 엣지 케이스

- [ ] 드래그 중 창 크기 변경 → 드래그 취소, 칩은 드래그 시작 전 자리로
- [ ] 자유 배치 후 창 크기 변경 → 비율 위치 유지, 화면 밖이면 가장자리 안쪽으로 보정
- [ ] 자유 배치 후 768px 미만으로 줄임 → 모바일 칩 목록으로 전환 (자유 배치 무시), 다시 넓히면 Home 위치
- [ ] 칩을 Nav 영역이나 화면 밖으로 던짐 → Hero 영역 가장자리 안쪽에 놓임
- [ ] 칩을 슬롯 위에 놓으면 슬롯에 들어가므로 자유 배치로 슬롯이 가려지는 경우는 없음. 다만 슬롯 바로 옆(판정 여유 밖)에 놓인 칩이 슬롯 일부를 덮을 수 있음 → **슬롯을 항상 자유 배치 칩보다 위 레이어**에 둠
- [ ] 드래그 중 탭 전환 / 포인터가 창 밖으로 나감 → 드래그 취소
- [ ] 빠르게 두 칩을 연달아 클릭 → 마지막 입력 기준
- [ ] Navigating 중 다른 칩 클릭 → 무시
- [ ] 좁은 데스크톱 폭에서 가장 긴 키워드(`Feedback으로 다듬는`)가 슬롯에 들어간 경우 → Ring과 겹치지 않음
- [ ] JS 로드 전·실패 → 칩 라벨과 Nav 링크는 보이고, Nav Pill은 링크로 동작
