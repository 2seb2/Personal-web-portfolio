## 1. 🗺️ 개념 지도 (Overview)

### **한 줄 요약:**

```
JS 내장 자료구조(배열, 객체, Set, Map)의 시간복잡도를 이해하고,
상황에 맞는 자료구조를 선택하는 기준을 익힌다.
```

### **이 주제가 왜 중요한가?**

- "왜 배열 대신 Set을 썼나요?", "더 빠른 방법이 있을 것 같은데 왜 이렇게 구현했나요?" 처럼 자료구조 선택 이유를 물어보는 경우도 많다
- 프론트엔드에서도 목록 필터링, 중복 제거, 빠른 탐색이 필요한 상황이 자주 있다

**관련 키워드 (마인드맵 형태로 나열):**

```
[JS 내장 자료구조와 시간복잡도]
├── Big O 표기법
│   ├── O(1), O(n), O(n log n), O(n²)
│   └── 최악의 경우 기준
├── 배열 (Array)
│   ├── 인덱스 접근
│   ├── push/pop vs unshift/shift
│   └── includes, sort, splice
├── 객체 (Object)
│   ├── 해시맵 구조
│   └── 키 탐색 O(1)
├── Set
│   ├── 중복 제거
│   └── has() O(1)
└── Map
    ├── 다양한 키 타입
    └── 순서 보장
```

### 배경지식 — 시간복잡도가 왜 중요한가?

> 같은 결과를 내는 코드도 어떻게 작성하느냐에 따라 성능이 수백 배 차이날 수 있다. 
데이터가 10개일 때는 느껴지지 않지만, 10만 개가 되면 O(n)과 O(n²)의 차이는 치명적이다. 
시간복잡도는 입력 데이터가 많아질수록 코드 실행 시간이 얼마나 늘어나는지를 나타내는 개념이다.
> 

**Big O 표기법이란:**

- 입력 크기(n)가 커질 때 실행 시간이 어떻게 증가하는지를 표현하는 방식
- 최악의 경우를 기준으로 표현하며, 상수는 무시하고 가장 높은 차수 항만 남긴다
- 예를 들어 `3n² + 2n + 1`이면 → `O(n²)`으로 표기한다

```markdown
n = 1,000일 때 대략적인 연산 횟수:

O(1)       →          1번  (입력 크기와 무관, 항상 동일)
O(log n)   →         10번  (입력이 2배 늘어도 1번만 늘어남)
O(n)       →      1,000번  (입력에 비례해서 늘어남)
O(n log n) →     10,000번  (정렬 알고리즘의 일반적인 복잡도)
O(n²)      →  1,000,000번  (이중 반복문)
```

## 2. 📖 핵심 개념 정리

### 2-1. 배열 (Array)

**개념 설명 (내 말로):**

> 
> 
> 
> 순서가 있는 데이터 목록. 인덱스로 바로 접근 가능하지만,
> 특정 값을 찾으려면 처음부터 끝까지 하나씩 봐야 한다.
> 앞쪽 삽입/삭제는 전체 인덱스를 재정렬해야 해서 비용이 크다.
> 

**시간복잡도:**

| 작업 | 복잡도 | 이유 |
| --- | --- | --- |
| 인덱스 접근 `arr[i]` | O(1) | 메모리 주소를 바로 계산 |
| 끝에 추가 `push` | O(1) | 맨 뒤에 그냥 붙임 |
| 끝에서 제거 `pop` | O(1) | 맨 뒤를 그냥 제거 |
| 앞에 추가 `unshift` | O(n) | 전체 인덱스를 한 칸씩 밀어야 함 |
| 앞에서 제거 `shift` | O(n) | 전체 인덱스를 한 칸씩 당겨야 함 |
| 값 탐색 `includes/find` | O(n) | 처음부터 끝까지 순차 탐색 |
| 중간 삽입/삭제 `splice` | O(n) | 이후 인덱스 전부 재정렬 |
| 정렬 `sort` | O(n log n) | Tim Sort 알고리즘 사용 |
| 전체 순회 `map/filter/forEach` | O(n) | 전체 요소 한 번씩 방문 |

**실제 코드 예시:**

```jsx
const arr = [1, 2, 3, 4, 5];

arr[2];           // O(1) ✅
arr.push(6);      // O(1) ✅
arr.pop();        // O(1) ✅
arr.unshift(0);   // O(n) ⚠️ 전체 밀림
arr.shift();      // O(n) ⚠️ 전체 당겨짐
arr.includes(3);  // O(n) ⚠️ 순차 탐색
arr.sort();       // O(n log n)
```

### **핵심 포인트:**

- `push/pop`은 O(1), `shift/unshift`는 O(n) — 앞쪽 조작은 항상 비용이 크다
- 탐색(`includes`, `find`)은 O(n) — 탐색이 자주 필요하면 Set/Object로

---

### 2-2. 객체 (Object)

**개념 설명 (내 말로):**

> 
> 
> 
> Key-Value 쌍으로 데이터를 저장하는 해시맵 기반 자료구조.
> 키를 알면 O(1)로 바로 접근할 수 있다.
> 단, 키는 문자열과 심볼만 가능하고, 순서는 ES2015 이후부터 삽입 순서가 유지되긴 하지만 완전히 보장되진 않는다.
> 
- **배경지식 — 해시맵이란?**
    
    > 해시 함수를 이용해 키를 특정 인덱스로 변환하고, 그 위치에 값을 저장하는 구조.
    키만 알면 연산 한 번으로 위치를 계산할 수 있어서 탐색/삽입/삭제가 모두 O(1)이다.
    > 

**시간복잡도:**

| 작업 | 복잡도 | 이유 |
| --- | --- | --- |
| 키로 접근 `obj[key]` | O(1) | 해시 함수로 위치 바로 계산 |
| 키-값 추가/수정 | O(1) | 해시 함수로 바로 삽입 |
| 키 삭제 `delete` | O(1) | 해시 함수로 바로 삭제 |
| 키 존재 여부 `in`, `hasOwnProperty` | O(1) | 해시 함수로 바로 확인 |
| 전체 순회 `Object.keys/values/entries` | O(n) | 전체 키를 다 봐야 함 |

**실제 코드 예시:**

```jsx
const obj = { name: 'kim', age: 20 };

obj['name'];              // O(1) ✅
obj['score'] = 100;       // O(1) ✅
delete obj['age'];        // O(1) ✅
'name' in obj;            // O(1) ✅
Object.keys(obj);         // O(n)
```

### **핵심 포인트:**

- 해시 구조라 탐색/삽입/삭제 모두 O(1) — 키를 알면 바로 접근
- 키는 문자열/심볼만 가능
- `Object.keys()` 순회는 O(n)

---

### 2-3. **Set**

**개념 설명 (내 말로):**

> 
> 
> 
> 중복 없는 값의 집합. 내부적으로 해시 구조라 탐색/삽입/삭제가 O(1)이다.
> 값의 존재 여부를 빠르게 확인하거나 중복을 제거할 때 유용하다.
> 

**시간복잡도:**

| 작업 | 복잡도 |
| --- | --- |
| 값 추가 `add` | O(1) |
| 값 존재 확인 `has` | O(1) |
| 값 삭제 `delete` | O(1) |
| 전체 순회 `forEach` | O(n) |

**실제 코드 예시:**

```jsx
const set = new Set([1, 2, 3, 4, 5]);

set.has(3);     // O(1) ✅ 배열의 includes와 다르게 O(1)
set.add(6);     // O(1) ✅
set.delete(1);  // O(1) ✅

// 중복 제거
const arr = [1, 2, 2, 3, 3, 4];
const unique = [...new Set(arr)];  // O(n)
```

### **핵심 포인트:**

- `has()`는 O(1) — 배열 `includes`(O(n))랑 헷갈리지 말 것
- 중복 제거 목적이면 Set이 가장 간결하고 효율적

---

### 2-4. Map

**개념 설명 (내 말로):**

> 
> 
> 
> Key-Value 쌍 저장은 객체와 같지만,
> 키로 어떤 타입이든 사용 가능하고(객체, 함수 포함) 삽입 순서가 항상 보장된다.
> 빈번한 추가/삭제가 있을 때 객체보다 성능이 좋다.
> 

**시간복잡도:**

| 작업 | 복잡도 |
| --- | --- |
| 값 추가 `set` | O(1) |
| 값 접근 `get` | O(1) |
| 키 존재 확인 `has` | O(1) |
| 값 삭제 `delete` | O(1) |
| 전체 순회 `forEach` | O(n) |

**실제 코드 예시:**

```jsx
const map = new Map();

map.set('name', 'kim');   // O(1) ✅
map.get('name');          // O(1) ✅
map.has('name');          // O(1) ✅
map.delete('name');       // O(1) ✅

// 객체를 키로 사용 가능 (일반 Object는 불가)
const userMap = new Map();
userMap.set(userObject, { score: 100 });
```

### **핵심 포인트:**

- Object랑 시간복잡도는 동일(O(1))하지만 키 타입 제한 없음
- 삽입 순서 보장, 빈번한 추가/삭제엔 Object보다 유리

---

### 2-5. 전체 비교표

| 작업 | Array | Object | Set | Map |
| --- | --- | --- | --- | --- |
| 탐색 | O(n) | O(1) | O(1) | O(1) |
| 삽입 | O(1) 끝 / O(n) 중간 | O(1) | O(1) | O(1) |
| 삭제 | O(n) | O(1) | O(1) | O(1) |
| 순회 | O(n) | O(n) | O(n) | O(n) |
| 순서 보장 | ✅ | △ (ES2015+) | ✅ (삽입 순서) | ✅ (삽입 순서) |
| 중복 허용 | ✅ | 키 중복 불가 | ❌ | 키 중복 불가 |
| 키 타입 | 인덱스(숫자) | 문자열/심볼 | - | 모든 타입 |

## 3. 🔍 깊이 이해하기

### **자료구조 선택 기준**

```markdown
순서가 중요하고 인덱스로 접근해야 할 때
→ Array

고정된 키-값 데이터, 키가 문자열/심볼일 때
→ Object

중복 제거, 값 존재 여부를 빠르게 확인할 때
→ Set

키-값 쌍인데 키 타입이 다양하거나 삽입 순서/빈번한 추가·삭제가 중요할 때
→ Map
```

### 프론트엔드에서 자주 쓰는 패턴

- 선택된 항목 관리 — Set으로 토글

```jsx
// 체크박스 목록, 태그 선택 등에서 자주 쓰는 패턴
const [selected, setSelected] = useState(new Set());

const toggle = (id) => {
  setSelected(prev => {
    const next = new Set(prev);
    next.has(id) ? next.delete(id) : next.add(id);  // O(1)
    return next;
  });
};

// 선택 여부 확인도 O(1)
const isSelected = selected.has(id);
```

- API 응답 데이터를 id 기준으로 빠르게 접근 — Object/Map

```jsx
// 배열로 받은 데이터를 id 기반으로 변환해두면 O(1) 탐색 가능
const users = [
  { id: 1, name: 'kim' },
  { id: 2, name: 'lee' },
];

// ❌ 매번 O(n) 탐색
const user = users.find(u => u.id === targetId);

// ✅ 한 번 변환해두면 이후 탐색 O(1)
const userMap = Object.fromEntries(users.map(u => [u.id, u]));
const user = userMap[targetId];
```

- 중복 제거 — O(n²) vs O(n)

```jsx
// 태그 목록, 카테고리 등 중복 제거가 필요한 경우
// ❌ O(n²) — filter + indexOf 조합
const unique = arr.filter((item, index) => arr.indexOf(item) === index);

// ✅ O(n) — Set 활용
const unique = [...new Set(arr)];
```

## 4. 🎤 구두 설명 연습

### "JS의 자료구조별 시간복잡도를 비교해서 설명해 주세요." 질문에 대한 답변 스크립트

```
[도입 — 자료구조를 두 그룹으로 정리]
JS에서 자주 쓰는 자료구조를 크게 두 그룹으로 나눌 수 있습니다.
순서 기반인 배열과, 해시 기반인 객체, Set, Map입니다.

[배열]
배열은 인덱스로 바로 접근할 수 있어서 arr[i]는 O(1)이고,
push/pop처럼 끝에서 처리하는 것도 O(1)입니다.
하지만 특정 값을 탐색하는 includes나 find는 처음부터 끝까지 봐야 해서 O(n)이고,
shift/unshift처럼 앞쪽을 건드리면 전체 인덱스를 재정렬해야 해서 O(n)입니다.

[객체, Set, Map]
반면 Object, Set, Map은 내부적으로 해시 구조라
탐색, 삽입, 삭제가 모두 O(1)입니다.
순회는 결국 전체를 다 봐야 하니까 네 가지 모두 O(n)입니다.

[마무리 — 선택 기준으로 연결]
그래서 순서나 인덱스가 중요하면 배열, 중복 제거나 값 존재 여부 확인이 필요하면 Set,
키-값 구조가 필요하면 Object나 Map을 상황에 맞게 선택하게 됩니다.
특히 키 타입의 다양성, 삽입 순서 보장, 빈번한 추가/삭제 여부까지 고려해서 Object와 Map을 구분해서 사용합니다.
```

### ⏱️ 1분 요약 버전

```
배열은 인덱스 접근은 O(1)이지만 탐색과 앞쪽 삽입/삭제는 O(n)입니다.
Object, Set, Map은 해시 구조라 탐색/삽입/삭제가 모두 O(1)이고, 순회는 모두 O(n)입니다.
순서와 인덱스가 중요하면 배열, 중복 제거나 값 존재 여부 확인이 필요하면 Set,
키-값 저장이 필요하면 Object나 Map을 씁니다.
특히 키 타입의 다양성, 삽입 순서 보장, 빈번한 추가/삭제 여부까지 고려해서 Object와 Map을 구분해서 사용합니다.
```

## 5. ❓ 예상 면접 질문 & 답변

> 
> 
> 
> 시간복잡도 질문은 독립적으로 나오기보다 "왜 이걸 선택했나요?", "더 빠른 방법은 없나요?" 형태로 꼬리를 물고 이어지는 경우가 많을 것 같다! 답변할 때는 시간복잡도 숫자만 말하지 말고, **왜 그 자료구조를 선택했는지** 이유까지 설명하면 좋을 듯!
> 

### 기본 질문

- **Q1. JS에서 자료구조를 선택할 때 어떤 기준으로 결정하나요?**
    
    > A:  크게 세 가지 기준으로 판단합니다.
    첫째, 순서나 인덱스 접근이 중요하면 배열을 씁니다.
    둘째, 값 존재 여부를 자주 확인하거나 중복을 제거해야 한다면 Set을 씁니다. 배열의 `includes`는 O(n)이지만 Set의 `has`는 O(1)이라 반복 탐색 상황에서 차이가 납니다.
    셋째, 키-값 쌍이 필요하다면 Object나 Map을 씁니다. 키가 문자열이고 구조가 고정된 단순 데이터면 Object, 키 타입이 다양하거나 동적인 추가/삭제가 많고 순서가 중요하면 Map을 선택합니다.
    > 
- **Q2. 배열 `sort()`의 시간복잡도는? (저번 주제 다시!)**
    
    > A: O(n log n)입니다. JS 엔진 구현에 따라 달라질 수 있지만, V8 같은 엔진에서는 Tim Sort 알고리즘을 사용하는데, 이는 merge sort와 insertion sort를 결합한 안정 정렬 방식으로 최악의 경우에도 O(n log n)을 보장합니다.
    >

### 꼬리 질문

- **Q3. 배열에서 앞쪽 삽입/삭제가 왜 느린가요?**
    
    > A: 배열은 인덱스 기반 구조라, 앞쪽 요소를 추가하거나 제거하면 나머지 모든 요소의 인덱스를 한 칸씩 밀거나 당겨야 합니다. 예를 들어 `unshift()`로 맨 앞에 값을 넣으면 기존 요소들이 한 칸씩 뒤로 밀리고, `shift()`로 맨 앞 값을 제거하면 나머지 요소들이 한 칸씩 앞으로 당겨집니다.
    그래서 `shift()`와 `unshift()`는 O(n)입니다.
    반면 `push()`와 `pop()`은 배열의 끝에서만 추가·삭제가 일어나기 때문에 기존 요소들의 인덱스를 바꿀 필요가 없어 O(1)입니다.
    > 
- **↳ Q3-1. 그렇다면 앞뒤 모두 O(1)로 처리할 수 있는 방법이 있을까요?**
    
    > A: JS 기본 자료구조에는 없지만, 이중 연결 리스트(Doubly Linked List)나 덱(Deque) 구조를 직접 구현하면 가능합니다. 실무에서는 인덱스 포인터를 두고 `shift` 대신 포인터만 앞으로 옮기는 방식으로 O(1)처럼 동작하게 구현하기도 합니다.
    > 
- **Q4. 배열에서 중복을 제거하는 방법을 설명해 주세요**
    
    > A: `filter + indexOf` 조합으로 구현할 수 있습니다. `arr.filter((item, index) => arr.indexOf(item) === index)` 처럼 작성합니다. 다만 `filter()`가 O(n), 내부 `indexOf()`도 O(n)이라 최악의 경우 O(n²)입니다.
    > 
- **↳ Q4-1. 더 효율적인 방법이 있을까요?**
    
    > A: `Set`을 활용하면 O(n)으로 줄일 수 있습니다. `[...new Set(arr)]`처럼 배열을 Set으로 변환하면 중복이 자동 제거됩니다. Set 내부가 해시 구조라 삽입이 O(1)이고, n개 요소를 처리하니 전체 O(n)입니다.
    > 
- **↳ Q4-2. Set 대신 Object로 해도 되지 않나요?**
    
    > A: 가능하지만 Set이 더 적합합니다. Object는 `{ value: true }` 형태로 억지로 키-값 구조를 만들어야 하고, 다시 배열로 변환하는 과정도 번거롭습니다. Set은 중복 없는 값의 집합을 표현하기 위한 자료구조라 목적에 더 맞습니다. 그래서 단순히 중복 제거가 목적이라면 Object보다 Set을 사용하는 게 더 적절합니다.
    >

### 🧨 함정/난이도 높은 질문

- **Q5. Object와 Map 둘 다 O(1) 탐색인데, 어떤 기준으로 선택하나요?**
    
    > A: Object와 Map은 둘 다 평균적으로 O(1)에 가깝게 탐색할 수 있지만, **데이터의 성격**에 따라 선택합니다. 
    정해진 필드를 가진 데이터, 예를 들어 사용자 정보나 설정값처럼 구조가 고정되어 있으면 Object를 사용합니다.
    반대로 실행 중에 키가 계속 추가되거나 삭제되고, 문자열뿐 아니라 숫자나 객체처럼 다양한 타입을 키로 사용해야 한다면 Map을 사용합니다. Map은 삽입 순서를 보장하고, `set`, `get`, `delete`, `has` 같은 메서드가 제공되어 동적인 Key-Value 관리에 더 적합*/`니다.
    즉 Object는 데이터 모델 표현, Map은 동적인 Key-Value 컬렉션 관리에 더 가깝습니다.
    >
